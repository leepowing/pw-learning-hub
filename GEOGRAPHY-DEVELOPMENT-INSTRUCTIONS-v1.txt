一、來源資料、內容準確性及地理學科完整性

1. 以使用者提供的 Geography Knowledge Organiser 為主要和權威資料來源。
2. 不可刪減、遺漏、改變或自行猜測原文的重要資料。
3. 必須保留所有：
   - Chapter title 及 section headings
   - Key Facts 及 Key Vocabulary
   - Place names、locations、regions、countries、cities 及 physical features
   - Geographic definitions、processes 及 relationships
   - Dates、statistics、percentages、rankings、distances、units 及 development indicators
   - Spatial patterns、distribution、density、scale 及 direction
   - Causes、effects、impacts、opportunities、challenges、responses 及 management strategies
   - Human、physical、environmental、social、economic 及 political factors
   - Case-study examples、stakeholders 及 place-specific evidence
   - Maps、keys、legends、symbols、labels、compass directions、scale bars及 annotations
   - Graphs、population pyramids、tables、datasets、photographs及 diagrams
   - 原文清單內每一個獨立項目
4. 可以改善文法或重組成適合 Year 8 閱讀的英文，但不可改變數據、地點、因果、空間關係或原意。
5. 不可自行加入來源沒有提及的知識，除非使用者明確要求，或為了解釋而加入極少量背景。
6. 所有非來源補充內容須標明 Additional context，並在 source metadata 標記 generatedSupplement。
7. 圖像、掃描、地圖、圖例、文字或數據不清楚時，列出 filename、page、位置及不確定內容並詢問使用者，不可猜測。
8. 如發現 KO 可能有過時數據、事實錯誤、拼寫問題、矛盾或不合理數值，先報告並取得決定，不可靜默改正。
9. Geography 的地點證據具有時間性；不得以網上較新數據自動取代學校 KO 的指定數據。
10. 不可把 general knowledge 當成 case-study evidence。題目要求 Brazil／Rio de Janeiro／Amazon 等指定地方時，答案及 rubric 必須使用該地方的可信來源內容。

一 A、老師補充文件整合及來源優先次序

1. 完整核對 KO 後，逐份核對老師工作紙、課堂題目、revision material、fieldwork booklet、atlas extracts、maps、graphs、teacher guide、answers 及 mark schemes。
2. 建立 Source Inventory，逐份列出：
   - filename
   - document type
   - page count
   - 對應 Chapter／section
   - 新增 knowledge／skill
   - 老師原題和答案位置
   - maps／photos／graphs／tables／datasets／fieldwork methods
3. 老師文件含 KO 沒有的 required content 時，加入最合適 section，並同步進入 Learn、Mind Map、Flashcards、Quiz 及 Coverage Matrix。
4. 老師正式補充內容在 metadata 標記 teacherSupplement，視為 required taught content，不標作普通 Additional context。
5. 每個來源點及老師原題保存：
   sourceType: knowledgeOrganiser | teacherSupplement | teacherQuestion | generatedSupplement
   sourceRef: filename + page + printed question number
6. 不可把本機絕對路徑、私人資料或敏感檔名傳到 client。
7. KO 與老師文件如有地點、數據、年份、答案或解釋衝突，列出差異並詢問使用者。
8. question paper 與 answer／mark scheme 必須按版本、題號、sub-part 及分值逐一配對。
9. 不可只抽取問題而遺漏其 map、photo、graph、table、dataset、legend、scale、source text、case-study context 或 model answer。
10. Knowledge Coverage 及 Teacher Question Coverage 均須達 100%，missing 為 0。

一 B、PDF 逐頁題目清單及「老師原題零遺漏」硬性閘門

1. 實收檔案數必須與預期檔案數對數。每份檔案分類為：
   - questionBearing
   - answerOnly
   - teachingOnly
   - duplicateVersion
   - unreadableOrBlocked
2. 所有檔案都須進入 Source Inventory；所有頁面須有 checked／blocked 記錄。
3. 編寫 Quiz 前建立獨立 PDF-QUESTION-MANIFEST；每個 task 及每個可獨立作答 sub-part 各有一行。
4. 每行至少包括：
   - stable teacher source question ID
   - filename、page、printed number、sub-part
   - exact original wording 及 command word
   - marks
   - question type
   - required map／photo／graph／table／dataset／passage／legend／scale
   - answer source
   - target section ID
   - implementation question ID
   - status 及 notes
5. 一個 manifest 記錄必須一對一映射到一個可追溯 Quiz 作答單位。
6. 題幹、指示、options、word bank、statements、map key、data labels、axis labels、units、marks、所有 sub-parts 及 answer lines 暗示的作答數目均屬原題，不可遺漏。
7. 題目重複不構成略過理由；只有使用者明確批准後可標記 ExcludedWithUserApproval。
8. 不可用自製題、相同知識點另一題、Flashcard 或 Learn 內容代替老師原題。
9. renderer 不支援時，先擴充 schema／renderer；未能可靠實作則標記 Blocked，且不可聲稱完成。
10. OCR 只可作初稿；每頁必須與 PDF 視覺核對，特別留意小字圖例、scale、direction、axes、percentages、colour bands、annotations及跨頁題目。
11. 編程前向使用者報告 expected／received／readable files、question-bearing files、answer-only／teaching-only files、pages、tasks、independently answerable sub-parts、各題型數量及 blocked items。
12. 預期檔案缺失、頁面未檢查或內容無法辨認時，不可開始大規模題庫編寫。
13. 分開維持：
   - Knowledge Coverage
   - Teacher Question Coverage
14. 最終只接受：files accounted 100%、pages checked 100%、teacher tasks implemented 100%、missing／blocked／unapproved exclusions／wording mismatches／missing context assets 全部為 0。

六、Flashcards——Geography Active Recall

1. 每個 required knowledge point、skill及Key Vocabulary都有source-mapped flashcard。
2. 每張卡使用固定、全域唯一card ID及有效section ID；發布後不可重新編號。
3. Fact card Front 必須是清楚、具體、可獨立理解的active-recall question。
4. 禁止：
   - Recall point 1: [Section]
   - What can you remember about this point?
   - Review this fact.
   - 只有section title、Fact number或topic heading
5. 合適的 Geography Front 可包括：
   - Where is ... located?
   - What is meant by ...?
   - What spatial pattern is shown by ...?
   - Why does ... occur?
   - How does ... lead to ...?
   - What are the push／pull factors for ...?
   - What evidence shows ...?
   - How does X compare with Y?
   - What does the map／graph／population pyramid show?
   - What are the causes／effects／responses?
6. Vocabulary Front 使用 Define [term].；重複term須加入最少而足夠的topic context。
7. 普通fact card原則上只測一個主要target；完整process、comparison、case-study evidence set或cause-effect chain才可測相連多點。
8. Back 必須完整、準確、可獨立理解，保留：
   - place name及location
   - spatial direction／distribution／scale
   - dates、statistics、percentages、units及rankings
   - named examples及stakeholders
   - cause-effect link
   - map／graph evidence
9. 不可只用泛化描述取代place-specific evidence。
10. Map／graph／photo內容如只靠文字不能有效回想，使用清晰可信asset或明確描述學生要讀取的部分。
11. 可使用以下card types：
   - Fact
   - Vocabulary
   - Place／Location
   - Map／Diagram
   - Data／Statistic
   - Process
   - Cause／Effect
   - Comparison
   - Case Study
   - Fieldwork
12. 每個Front在Chapter內唯一；整個Geography flashcard bank亦不可有無法分辨context的相同Front。
13. Back非空並逐字對應已審核source point，或記錄為approved faithful version。
14. 卡數由required facts、vocabulary、places、statistics、maps、graphs、processes及case-study evidence推導，不可主觀設定。
15. 點擊翻卡；答案後可選I remembered／I need more practice，並有左右飛走動畫。
16. 顯示Remaining、Remembered、Need practice、Accuracy。
17. 只使用taught sections，開始或重新開始時shuffle；card ID及progress mapping不變。
18. 每section報告各card type及總數。
19. 人工抽查每section第一張、中間一張及最後一張Front／Back。
20. desktop、laptop、iPad、mobile檢查長地名、長答案、statistics、lists、maps及buttons。
21. 優化既有Chapter時，未經批准只可改Front；ID、section assignment、Back、總數及coverage denominator保持不變並建立before／after audit。

六 A、Flashcard 自動驗收硬性閘門

以下全部須為PASS：

1. total cards等於資料實數、section加總及頁面顯示。
2. duplicate card IDs = 0。
3. invalid section IDs = 0。
4. empty Fronts／Backs = 0。
5. generic Fronts = 0。
6. normalised duplicate Fronts = 0。
7. fact Front為具體完整問句，通常以問號結尾且至少四個有效英文詞。
8. vocabulary Front符合Define格式。
9. missing source mappings = 0。
10. Front／Back／source alignment通過；statistics、place及units無錯配。
11. required knowledge及vocabulary flashcard coverage = 100%。
12. 既有Chapter優化時，IDs、order traceability、section assignment、Back、card count及denominator完全對數。
13. 輸出Chapter及section級count、quality、source alignment及coverage報告。
14. 自動驗收不能取代人工翻卡及responsive測試。

七、Quiz 題型

題庫可包括：

1. Multiple Choice
2. Short Questions
3. Long Questions
4. 內容或老師原題需要時加入Interactive／Structured Questions：
   - Matching
   - Fill in the blank／cloze
   - Label a map／diagram／photo
   - Ordering／sequence
   - Classification／sorting
   - True／false並改正錯誤敘述
   - Map／choropleth interpretation
   - Graph／population-pyramid／table／data interpretation
   - Photo／source interpretation
   - Fieldwork method／sampling／risk／data question
5. Quiz首頁動態顯示Multiple Choice、Short Questions、Long Questions、Interactive Questions（有題才顯示）及Mixed Quiz。
6. 每類顯示taught sections下實際可用題數；0題則停用並顯示No questions available yet。

八、Quiz題數選擇

1. 選題型後再選5、10、20或All available；不可顯示超過實際可用數目的選項。
2. 題數很少時動態顯示1、2、All N。
3. All使用該類所有已解鎖題目。
4. 開始前顯示quiz type、available questions、session size及included sections。
5. 提供Back to quiz types。

九、Quiz與Taught Sections

1. 只使用已教授sections。
2. 多section題只有全部required section IDs taught後解鎖。
3. 改變selection後，各題型、subtype及Mixed counts立即重新計算。
4. 不得洩露未教授section的題目、context、map answer、marking points或feedback。

十、Randomisation

1. 每次開始及Try again重新randomise題目。
2. MCQ options每次randomise，正確答案判斷保持不變。
3. Matching只可randomise顯示順序，不可改變配對。
4. Ordering題可randomise起始順序，不可改變可信答案。
5. Map labels／graph data不可被randomisation改寫。

十一、Mixed Quiz

1. 混合所有可用主要題型。
2. 題數足夠且各類有題時，每種主要題型至少一題。
3. All包含所有已解鎖題目，不可遺漏Interactive題。
4. 只有某類完全沒有題目時才可不包含。

十一 A、Cross-Chapter Exam Revision Quiz

1. 在Year／Subject Geography首頁加入Exam Revision／Cross-Chapter Quiz入口。
2. 使用穩定route，例如：

十二、Multiple Choice

1. 每題包括question、四個合理options（適用時）、correct answer、explanation及mark value。
2. Distractors須合理並針對常見Geography misconceptions。
3. 不可含糊或有多個合理正確答案。
4. 學生選答案後才能Check answer。
5. 顯示Correct／Incorrect、correct answer及source-faithful explanation。
6. 答案位置randomise。

十二 A、Geography題目設計及command words

1. 題庫按來源適當包含：
   - Define／Name／State
   - Locate／Identify
   - Describe
   - Explain
   - Compare
   - Suggest
   - Analyse
   - Assess／Evaluate
   - Interpret a map／graph／photo／table／population pyramid
   - Use data／evidence
   - Calculate（如population density、change或percentage）
2. State／Name：短而準確，不暗中要求原因。
3. Locate：要求正確place、relative location、direction或map reference，按題目所給資訊評分。
4. Describe：指出pattern、feature、trend或發生內容，不暗中要求原因。
5. Explain：要求how／why及完整cause-effect link。
6. Compare：直接提及兩個對象，提供similarity及／或difference，不能只分開描述。
7. Suggest：接受多個合理答案，但只按可信context及rubric評分。
8. Analyse：必須使用提供的data、map pattern、trend、anomaly、numerical comparison或source evidence。
9. Assess／Evaluate：按題目要求考慮evidence、不同因素／stakeholders、limitations及supported conclusion。
10. Calculate：提供所有需要數據，處理working、answer、rounding及unit。
11. 不可把普通describe／explain題改成需要judgement的essay。
12. 學生未獲source map／graph／dataset時，不可要求讀取它。

十二 B、老師原題優先

1. 完整實作所有questionBearing PDF內每個task／sub-part後，才用generatedSupplement補coverage。
2. 原題保留spelling、punctuation、command word、order、sub-parts、options、maps、photos、graphs、tables、data、marks、units及instructions。
3. 只允許換行、HTML escaping、無語意空白正規化及紙本answer line轉成input；其他改字列入wording-diff並取得批准。
4. 老師answers／mark scheme優先作trusted answer、accepted answers、marking points及model answer。
5. 每題保存全域唯一question ID、teacherQuestionId、sourceType及sourceRef。
6. schema不支援時先擴充renderer，不可改成另一條普通short question。
7. 原題依賴asset時必須使用可信原asset；沒有map、graph、photo、legend、data或source passage即屬未實作。
8. 答案缺失或有多個合理答案時標記needsReview並詢問使用者。
9. 排除題目前必須列出完整資料並取得明確批准。

十二 C、Interactive／Structured Questions

1. 只在內容或老師原題適合時加入。
2. Schema可使用：
   matching、fillBlank、labelDiagram、labelMap、ordering、trueFalse、classification、mapInterpretation、dataInterpretation、photoInterpretation、fieldworkStructured。
3. Label map／diagram：
   - 使用可信清晰asset
   - 固定label targets及座標
   - 不可額外畫指示線遮蓋原圖
   - 若原圖已有箭嘴，只在箭嘴附近加號碼或可存取target
   - 提供keyboard-accessible fallback
4. Map interpretation保留title、key、scale、direction、data class及source year。
5. Graph／population pyramid保留axes、labels、units、legend、year及完整data。
6. Matching配對必須唯一；右側可randomise但關係不變。
7. Fill blank保存accepted answers，處理大小寫、空格、英式拼法及真正同義詞，不可用過寬substring。
8. Classification保存明確categories，例如human／physical、push／pull、cause／effect、social／economic／environmental。
9. Ordering只使用唯一或明確接受的sequence。
10. Fieldwork題分開處理question、method、sampling、equipment、risk、data presentation、reliability及conclusion。
11. 固定答案優先deterministic marking；需要語意判斷的解釋部分才交AI。
12. 每種新題型具備renderer、answer state、Check answer、feedback、score、retry、results、filtering、randomisation及accessibility測試。

十三、Short Questions

1. 每題包括question、total marks、獨立marking points及improvement guidance。
2. 每一分對應一個可獨立取得的marking point；不可把多個事實塞入一點。
3. 題目說明需要多少項；完整清單使用Name all／Give all。
4. 使用server-side AI按可信題庫評分。
5. 接受意思相同的寫法、合理同義詞及不影響意思的輕微拼字／文法錯誤。
6. 不可只靠keyword；place、direction、data、unit及因果錯誤不得因出現關鍵詞而得分。
7. 含糊或欠重要detail只可Partly met。

十四、Long Questions

1. 包括question、total marks、criteria、suggested structure、improvement guidance及AI rubric。
2. 按來源及題目合理使用4、6或9 marks，不固定套用History essay分數。
3. 可測試：
   - physical／human process
   - cause-effect chains
   - opportunities and challenges
   - comparison of places／groups／strategies
   - map／graph／data analysis
   - case-study application
   - management／sustainability evaluation
4. Case-study題要求準確named place及可信place-specific evidence。
5. Explain要求完整mechanism或causal chain；Compare要求直接比較；Analyse使用source evidence；Evaluate才要求平衡證據及supported conclusion。
6. 未明確要求assess／evaluate／judgement時，不可強迫學生加入結論。

十四 A、AI評分通用規則

1. AI逐項評核trusted marking points，狀態只可為：
   - Met：完整符合，1分
   - Partly met：方向正確但不完整，0分
   - Not met：缺失、錯誤或無關，0分
2. AI不可新增、刪除、合併、改寫或重新排序criteria。
3. Server驗證criterion數量、ID、次序及schema。
4. 最終分數由server按Met數量重算，不直接相信AI total。
5. 分數介乎0至maxMarks。
6. 顯示文字採用server可信criteria，不使用AI改寫版本。
7. Server重建或嚴格驗證summary，準確顯示Met／Partly met／Not met數量。
8. Summary列出所有Partly met尚欠資料及所有Not met，不可只提第一項。
9. strengths、missedPoints、improvements及improved answer不可與criteria status矛盾。
10. 顯示AI MARK、score、summary、逐項status及explanation、What went well、How to improve、Points to add、Example improved answer。
11. Example improved answer必須涵蓋全部trusted criteria，並符合題目command word。
12. 保留提示：AI marking is advisory, and a parent or teacher can review it.

十四 A-G、Geography AI評分專項規則

1. 地理準確性優先；正確關鍵詞配上錯誤地點、方向、scale、statistics、unit、process或因果不可判Met。
2. Case-study criterion如要求place-specific evidence，泛化全球描述不可取得該點。
3. 接受：
   - 合理Geography同義詞
   - 正確縮寫及全寫（來源及年級適用時）
   - 數值的等值格式
   - 不改變意思的英式拼寫變化
4. 不接受：
   - population distribution與population density混淆
   - urbanisation與rural-urban migration混淆
   - push factor與pull factor倒轉
   - cause、effect及response互相混淆
   - human與physical factor錯分
   - map direction、location、scale或pattern錯誤
   - graph trend或population-pyramid年齡／性別解讀倒轉
   - 有正確詞語但causal link錯誤
5. Describe pattern criterion要求可信pattern，例如concentrated／sparse、coastal／inland、increase／decrease及必要exceptions；只寫high／low通常不完整。
6. Explain criterion要求criterion列出的因果連結；零散正確事實不可當完整explanation。
7. Compare criterion必須直接連接兩個對象；只描述其中一方或兩段不相連資料最多Partly met。
8. Data題檢查trend、comparison、anomaly、numerical evidence、date及unit；不能只因寫increase／decrease給完整分。
9. Map題只按可信map data及legend評分，不以外部常識代替。
10. Numerical題按需要拆成formula、substitution、calculation、rounding及unit；固定數值優先deterministic checker。
11. Photo／source題只可根據畫面可見evidence及題目context評分，不可要求學生知道圖片外資訊。
12. Fieldwork題準確區分sampling、accuracy、reliability、representativeness、bias、risk及method improvement。
13. Make it better／more accurate／more reliable等籠統回答，沒有具體方法及理由時只可Partly met或Not met。
14. Evaluate management／sustainability時，只在trusted criteria要求下評核trade-offs、stakeholders、short／long term、scale及supported conclusion。
15. Contradiction rule：答案後段明確否定前段正確陳述時，不可忽略矛盾並給完整分。
16. Outside knowledge不額外加分，亦不可加入來源沒有教授的額外滿分要求；只在與trusted criterion矛盾時影響判斷。
17. Model answer使用準確place names、data、dates、units及Geography vocabulary，只涵蓋可信題庫要求。
18. 修改shared AI route後，同時執行Geography專項測試及History、Science、English regression。

十四 B、API安全與錯誤處理

1. OPENAI_API_KEY只放server-side environment variable。
2. 不可放client、browser、localStorage、public env、Git、console或error message。
3. Browser不可直接呼叫OpenAI；使用現有server route。
4. Server根據可信question ID取得question、marks、criteria及context asset references。
5. 驗證request body、ID、answer length、response schema及score range。
6. Loading期間停用重複提交。
7. API失敗／逾時保留學生答案和session，顯示安全重試訊息，不洩露prompt、stack trace或secret。

十四 C、AI評分測試

Short Questions至少測試：
1. 0分、部分分、滿分。
2. 同義表達及輕微拼寫錯誤。
3. 只答中criterion一部分。
4. 正確詞語但地點／方向／因果錯誤。
5. 部分正確但自相矛盾。
6. 清單題的空白、部分及完整答案。

Long Questions至少測試：
1. 低、中、滿分。
2. 欠place-specific evidence。
3. 欠direct comparison。
4. 欠data evidence。
5. Evaluate題欠supported conclusion。
6. 接近滿分但欠一criterion。

每次核對：
1. score等於Met數量。
2. Partly／Not met不得分。
3. criteria文字及順序與trusted data一致。
4. feedback、Points to add及improved answer一致。
5. 重複評分結果合理穩定。
